# R1 会话、编辑与发布版本验收

2026-10-02。分支 `codex/r1-content-context`，基于 R0 `8873195`。实现架构报告 B4/B7/B8/B9，下一阶段为 R2。保留现有 React/TanStack Query、Hono/Drizzle、jobs 和 shared。

## 实现范围

- 会话模块以原子授权记录/epoch 中止旧请求；每代新的 QueryClient 清掉旧查询和 mutation，重新挂载路由/编辑器/通知。JSON、CSV、multipart 从请求到 body 读取均校验原会话，旧 401 不清新用户。多步分析/保存/封面/图片/重试绑定捕获的会话。跨标签页授权同样生效。
- 原来按全局键保存的屏蔽词、库偏好、已看笔记、分析定位改为用户键；历史无归属键原样保留，不迁移给碰巧登录的用户。主题、列表外观等纯展示偏好维持原行为。
- `DraftEditSession` 集中本地待保存记录、按草稿串行写、文字 CAS、失联 ACK 核对、恢复与冲突决策。每次变更先保存本地；不同窗口独立记录，不用一个 ref 承担失败恢复。文字/写作账号 PATCH 缺 textVersion 428、旧版本 409；图片仍独立 imagesVersion。错误/冲突会阻止标记就绪和成稿前保存确认。允许用户查看服务器文字，明确保留自己的改动重存或使用服务器版本。
- 分析建议入池传报告/索引和目标账号，服务端校验归属/建议/引用，保存 immutable analysisSource。晚些从选题池成稿仍采用具体来源及该次定位；账号未变时保留定位，当前风格/红线完整冻结；换账号不复用旧定位。报告、引用或账号失效明确报错。历史报告不会因为人设编辑而变化。
- 发布原版本重试独立端点，复制正文图集、人设、身份、封面、策划快照与可见性，改为立即排队。operationId 抵御双击/提交后断线；已有有效子任务时另一操作不能重复排。未知结果与不完整旧失败不允许重试。确认页显示原版本、当前变化与原/当前红线，独立提供“用当前稿新建”。新建也核对确认时的文字/图片/人设版本；并发修改要重新确认。

## 实际工作台验证

使用独立内存 Hono `127.0.0.1:3601` 与 Vite `127.0.0.1:5181`，账号 `r1-a/b@preview.invalid`、内容与小红书身份均为合成测试数据，**不是生产 admin@devin.local（ID #2）**。没有 worker 或站点执行插件，排队不能造成真实发布。

已在 Chrome 核对：

1. 模拟保存 503，编辑正文后切到第二篇，再切回及刷新，仍显示本地正文和保存失败，未假显示已保存。
2. A 退出→B 登录，队列/正文只显示 B；回 A 后恢复原本地改动，恢复连接成功保存。
3. 两窗口同版本分别改标题/正文。第一窗口成功，第二窗口出现冲突并保留本地正文；查看最新标题后明确保留本地，最终同时保留新标题和自己的正文。
4. 后改草稿标题/正文/账号人设，发布列表仍显示原标题；重试确认页显示原正文/图序/可见性/旧人设与当前差异。确认后仅在内存库生成一个原标题待执行任务，未点“通知插件立即执行”。
