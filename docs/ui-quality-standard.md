# 前端品质标准

2026-10-03，用户要求以 Awwwards、Webby Awards、FWA 能获奖的品质为目标，持续自检、修正和复查。沿用简洁中文、柔和圆角矩形、克制的 Apple 风格与 Typefully 的创作工作区方向。

## 参照与判断

- Awwwards 的公开评分页使用设计、可用性、创意、内容四个维度。本项目借鉴其对整体完成度的要求，评价对象包括实际工作区和状态，不能只看首页截图。[官方评分实例](https://www.awwwards.com/sites/acme)
- Webby 的网站评审涵盖内容、结构与导航、视觉、功能、交互、创新及整体体验，并强调清晰的内容、包容性和技术对体验的帮助。检查要覆盖完整动作及退出路径。[官方评审标准](https://www.webbyawards.com/judging-criteria/)
- FWA 的定位包含数字创新。这里的辨识度来自采集素材、编辑正文、平台预览、发布证据之间的连续体验，使用有明确用途的反馈与动效。[官方周年说明](https://thefwa.com/FWA25/25.html)

以上是项目对品质的要求与解读；内部自检记录不代替奖项评审，也不使用虚构评委分数或获奖标志。

## 每次改动的验收

| 维度 | 自检要求 |
|---|---|
| 视觉 | 字号、间距、颜色和圆角有一致层级；正文、真实封面与操作是主体；标题直接用功能名 |
| 内容 | 无口号、重复介绍、无依据数据和英文占位；错误、未知结果、确认、保存冲突和统计范围仍明确 |
| 交互 | 指针与键盘都可完成动作；状态即时响应；退出和返回可发现；重试、归档、确认遵循原领域规则 |
| 焦点 | 有可见焦点和跳过导航；弹层打开后进入其内，Tab 循环，Esc 关闭最内层，退出后返回触发处；退出动画期间禁用旧弹层 |
| 响应式 | 检查 390px、768px、1024px、1440px；不得整体横向溢出。复杂表格保留明确的内部横向滚动；窄屏优先正文和内容 |
| 可读性 | 普通文本的核心配色至少 4.5:1；浅色、暗色、占位文字和状态都检查。参考 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) |
| 动态效果 | 高频操作即时完成；普通反馈约 100–220ms；指针按压克制。尊重减少动态效果、减少透明度和高对比偏好 |
| 性能 | 复用系统字体，不增加装饰库或无用途动画；检查构建产物、图片加载与控制台；复杂页面继续按路由拆包 |

每次先观察现有页面，再实施、截图与实际操作复验；发现问题就再修一轮。最后一轮需重新检查改过的路径、共用组件和邻近页面。记录检查环境及真实结果，未检查的设备或行为不得标成通过。颜色、类名、静态布局不写镜像单测；交互以实际操作验证，保留必要的领域与权限回归。

弹层键盘行为参考 [W3C 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。新动作仍遵守原有会话、账号和版本约束。
