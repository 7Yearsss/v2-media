# T1 图片上传：实现与验收记录

2026-10-02。实现分支 `codex/draft-image-upload`，与主工作区的生产库连接服务隔离。没有在生产执行迁移、清理测试数据或发布新笔记。

## 已实现

- 上传接口需鉴权，multipart 单文件接收后持久暂存；server job 处理 JPEG/PNG/WebP、校正方向、去元数据并存 R2。缺 R2 提示不可用，不能把本地临时 URL 当完成素材。
- 草稿图片区支持选择多图、拖放、状态轮询、失败重试、排序与移除；首图为封面，保留 URL 入口。上传占位在接收时确定顺序，刷新可恢复。
- 图集版本阻止旧快照覆盖后台完成的图片；文字保存改成字段 PATCH、串行发送，可重试失败保存。切草稿只更新发起上传的草稿。
- 新发布任务保存正文与图集快照；未处理完成的图不能发。图片在移除/取消后的迟到回执不能重新挂回草稿。
- 新 upload/cover 前缀供正式读取，GC 识别草稿与发布快照引用，并保护引用中的媒体。容量不足拒绝新上传处理。

## 自动化与页面验证

全仓 `npm run typecheck`、`npm test`（13 文件、112 用例）、`npm run build:ext`、web build 均通过。web 构建仍提示已有的大 bundle 体积，不影响产物生成。

专项测试在内存 PGlite/mock R2、独立暂存目录运行，覆盖异步接收、模拟 worker 重建、乱序完成、内容去重、正式对象读取、跨用户拒绝、R2 缺失、超限/不支持格式、幂等、图集版本冲突、移除后的迟到回执、退避与手动重试、发布快照及容量压力下的 GC 保留。

独立 UI 环境端口为 server 3001/web 5174，数据库与 R2 均为测试实现。测试三张不同的编号图片：

1. HTTP 上传依次得到 202，后台处理后都可读取，三张顺序为 1/2/3。
2. 页面将图 2 前移，首图/右侧预览变为 2，图序 2/1/3。
3. 修改标题后立即切换另一个草稿，另一篇无图片；切回并刷新，文字和图序仍保留。
4. 页面移除图 3 后，图集与预览均变为两张。

浏览器工具已打开文件选择器，但缺少 ChatGPT Chrome 插件的本地文件读取权限，不能自动 setFiles。没有改浏览器权限；改用本地 HTTP 调用验收接收通路。选择器和拖放入口存在，但通过浏览器真正选入文件/拖放上传仍需手工验收。没有把这一限制或 mock R2 结果当作线上验收。
