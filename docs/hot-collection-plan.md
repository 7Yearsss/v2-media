# 热点筛选与自动深度采集规划

2026-09-30。第一版点赞筛选已实现于插件 0.1.4；高级热度条件和自动浏览任务仍为后续规划。

## 已有能力与缺口

- 列表/搜索/推荐流已解析点赞数，详情另有收藏、评论、分享、发布时间、正文与素材。
- 部分列表字段缺失时解析器会填 0；不能把列表里的 0 当作已确认的收藏数或评论数。
- 原先自动采集只补正文，没有触发深度评论任务；本次已接入入库成功后的顺序队列。
- 当前深度队列一次开一个详情页，容量 30，按 noteId 去重；遇到验证需要人工处理。它尚不是可配置的搜索/浏览任务。
- 插件 0.1.4 支持自动采集最低点赞门槛。没有曝光/浏览量数据，不能计算真实互动率。

## 第一版：按点赞数筛选

在插件设置增加「只自动采集热门笔记」，默认关闭以保持已有行为；开启后输入「最低点赞数」。边界是 `likes >= minLikes`，只影响自动采集，手动点采集始终可用。

可提供 500 / 1000 / 3000 三个快捷值和自定义整数。这些是可调整的起始值，不是平台官方爆款标准；建议试运行后按领域实际命中率调整。

配置示例：

```json
{
  "autoCollect": true,
  "deepCollect": true,
  "hotFilter": { "enabled": true, "minLikes": 1000 },
  "collectionId": 12
}
```

处理链：嗅探卡片 → 判断点赞门槛 → 不达标仅暂存页面缓存 → 达标补详情并入库 → 开启深度采集则串行补评论。先筛选再发详情请求，减少无效请求和入库噪点。详情单独到达时也必须过门槛，防止绕过筛选。

已入库笔记的后续详情/评论补传继续完成，沿用首次入库时的规则和目标库。调整门槛不删除已有笔记，未开始的任务按最新规则重新评估。页面缓存需要刷新最新点赞值，使后来达到门槛的笔记仍能采集。

浮层显示「发现 40 · 符合 6 · 入库 6 · 待补评论 2 · 失败 0」，并给出跳过原因，例如「点赞 820，低于 1000」。

## 第二版：高级热度与时效

增加最低收藏数、最低评论数、发布时间范围、关键词/排除词和内容类型。条件默认全部满足，界面明确说明。收藏、评论、时间未确认时状态为「待核验」，获取详情后再决定，不能直接以缺省 0 拒绝。

如果需要综合热度，可选择自定义权重，例如 `点赞×1 + 收藏×2 + 评论×3 + 分享×2`，明确标注「自定义热度」，展示计算明细。此公式是产品规则，权重可改，不代表平台内部推荐分。

「最近 7 天且点赞 ≥ 1000」用于近期高互动内容；长期高赞和正在增长的热点分开看。要识别上升热点，需保存多次互动快照并比较每小时增量，单次采集无法判断增长速度。

## 第三版：自动浏览任务

工作台创建任务：搜索关键词 / 指定作者 / 当前推荐页，选择目标库、热度条件、扫描上限、入库上限、评论采集上限和间隔。搜索结果优先使用站点可用的排序筛选，再由插件逐条核验规则。

任务流程：启动 → 串行滚动发现 → 筛选 → 逐篇详情 → 入库 → 评论补齐；支持暂停、继续、取消与失败重试。浏览器关闭则任务停止；遇到登录失效、验证或页面拦截则全队列暂停，用户处理后再恢复。

任务与每篇笔记分别记录发现、跳过、待详情、已入库、待评论、完成、部分完成、失败。评论总数与实采数分别显示，并明确是否包含子回复；不得把只收到一页评论标成全量完成。

全浏览器共用队列，限制请求和标签页并发；保存规则与目标库快照。任务页不再触发额外自动采集，按用户+平台+noteId 幂等入库。长期任务写入持久状态，SW 重启可恢复；服务端保存任务记录，浏览器插件执行。

## 实施顺序与验收

1. 自动深度采集修复与真实登录态复测：无需手动点采集，卡片→详情→评论可完成；禁用自动/深度后不继续开新任务页；隐藏任务不递归入队。
2. 点赞门槛：共享类型/纯规则函数先定义，随后设置与浮层接入。测试 N−1 / N / N+1、重复事件、详情独立到达、数值格式、设置变更、手动绕过筛选、未入库评论不得创建笔记。
3. 浏览任务和目标库快照：测试暂停恢复、队列溢出、超时、验证、SW 重启、取消后不再自动入库以及跨用户隔离。
4. 高级条件和增长热点：先补「字段是否已确认」与快照契约，再上综合评分和增量排行。

首版验收样例：设置点赞 ≥ 1000，页面出现 999 / 1000 / 1001 赞的三篇笔记，自动采集后两篇；这两篇进入深度队列，评论状态单独显示；手动采集 999 赞笔记仍可成功。
